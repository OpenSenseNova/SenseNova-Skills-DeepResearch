# Report HTML

把报告文本创作为一份有编辑判断、网页美感、证据秩序、且只属于这份主题的单文件 HTML。

核心原则：**保留事实断言，重构阅读和视觉体验，让设计从报告所属领域和内容任务里长出来。主题自己的世界——它的材质、工具、器物与语汇——是产生独特设计选择的来源。**

## 设计判断原则

- **首屏即论点**：首屏先找到这份报告所属领域里最有识别度、最能承载主题气质的事物或机制，并用最适合它的形式呈现：标题、图片、动画、实时演示或一个可互动瞬间。这个选择必须有明确判断；不要默认使用“大数字 + 小标签 + 辅助统计 + 渐变强调”，只有当它确实是主题最自然、最有力的入口时才使用。
- **文字系统承载页面性格**：标题字体与正文字体要被有意搭配，不要沿用任何项目都能套上的常用字体组合；同时建立清晰的字阶，并有意识地设置字重、字宽和间距。让文字排印本身成为设计中可被记住的一部分，而不是只负责传递内容的中性容器。
- **结构即信息**：编号、眉题、分隔线、标签等结构性手段，应该传递内容的真实信息，而不是装饰内容。许多通用设计都使用编号标记（01/02/03），但这仅适用于内容本身就是一个序列的情况——例如一个真实的流程或一份文字时间线，其中顺序承载着读者所需的信息。在使用编号标记之前，请先思考其是否真的有意义。
- **有意识地使用动效**：先判断动效是否能服务主题、阅读或信息理解，再决定用在哪里：页面加载序列、滚动触发展示、悬停微交互或环境氛围。一个被编排好的关键动效通常比零散特效更有力量；动效选择必须服从整体美学方向。有些主题更适合克制处理，额外动画反而会削弱专业感，并让页面显得像 AI 生成的模板作品。
- **复杂度匹配愿景**：视觉方向越繁复，执行就越需要足够的层次、细节和完成度；视觉方向越极简，间距、字阶、对齐和微细节就越要精准。优雅不等于少，也不等于多，而是把选定的方向执行到位。
- **认真处理文案**：标题、导语、标签、按钮和说明都要被当作设计的一部分处理。可以对源报告的内容重写、压缩、合并和组织表达，但不得发明事实、口径或结论强度。文案和视觉一样会产生模板感。

## 设计知识的使用方式

- **层级**：先决定读者第一眼、第二眼、第三眼分别看什么，再分配尺度、重量、留白和位置。
- **对比**：用字体气质、字号、明暗、密度、动静和空间关系制造差异；不要只靠颜色强调。
- **对齐与网格**：正文、图表、卡片、注释和导航都落在同一套网格和宽度档里，避免右边缘和左基线随手漂移。
- **邻近与分组**：证据靠近判断，注释靠近对象，相关项成组，不相关项拉开。
- **重复与变奏**：重复建立秩序，变奏表达章节差异；整页不能一章一个系统，也不能每章完全同形。
- **图地关系**：纹理、背景、氛围和动效永远退到内容之后，不能抢走正文和证据的可读性。
- **节奏**：长报告要有轻重、疏密、转场和停顿；不是把所有模块等权堆叠。

## 硬规则

- Markdown 是素材，不是页面结构；不要逐段照搬，也不要把所有内容塞进卡片。
- 先写 `plan.md`，再写 HTML；没有完整 plan 不动 HTML。
- `plan.md` 必须在读取报告后立即作为一次独立的文件编辑写入运行时声明的绝对路径，并在继续前重新读取，确认文件存在且非空。
- `report.html` 必须增量构建：先用一次文件编辑写入完整但最小的 HTML 骨架，再按章节用多次小型编辑补充内容。任何一次文件编辑或补丁的文本负载不得超过 24 KiB；不得尝试在一个模型响应或单次工具调用中写完整长报告。
- 每完成 2-3 个章节就重新读取文件尾部，确认内容已经落盘。交付前再次读取 `plan.md` 和 `report.html`，确认它们位于运行时声明的输出路径，而不是仓库根目录或 Prompt 目录。
- 页面默认是单文件 HTML：语义 HTML + 内联 CSS；除非用户要求或项目已有资源体系，不拆分文件、不引 CDN。
- 可以用领域隐喻组织视觉和结构，但页面里的数字、来源、案例、判断、结论强度必须来自原报告。
- 不发明 logo、客户、证言、排名、地图点位、图表数据、置信度或看似合理但原文无法支撑的归纳。
- 图表、流程、时间线、地图式分组等必须自包含手写。

## 工作流

1. **读内容与任务**：通读源报告，确认主题、领域、受众、用途、核心判断、证据、限制、重复内容、表格、图示和附录。
2. **第一遍：brainstorm 短设计计划**：先根据 brief、报告领域、内容任务、证据结构和受众发散 2-3 个与内容契合的设计方向，不碰具体 HTML。每个方向用 compact token system 表达：Color 为 4-6 个命名 hex 值并说明语义用途；Type 定义 display、body，必要时定义 utility / mono；Layout 用一句话概念和 ASCII wireframe 描述；Signature 定义这页唯一会被记住的设计元素。
3. **审查并修订短设计计划**：对照 brief 和报告内容检查每个方向是否真有内容来源。如果任何部分像类似页面的通用默认答案，而不是为当前报告做出的选择，必须修订该部分，并写明改了什么、为什么改。确认相对独特性后，选择 1 个方向进入完整计划。
4. **第二遍：完整页面计划**：基于修订后的短设计计划，展开信息结构、首屏策略、页面拓扑、导航、章节版面、转场节奏和证据贴附方式；用层级、对比、对齐、邻近、分组、重复 / 变奏来组织信息。
5. **逐章做内容设计**：每章写清 `内容形状 -> 章节版面 -> 呈现形式 -> 排版处理`。颗粒度到段或判断，不要整章放过；长论述也要做导语、拉引、边注或判断提块。
6. **定设计契约与 checklist**：写 HTML 前把 tokens、字体角色、宽度档、章版面映射、动效策略、响应式降级、事实边界、泛模板自检和检查角度落到 `plan.md`。checklist 是开工前的契约，不是事后补救。
7. **写 HTML**：只实现 `plan.md`，不要在 HTML 阶段另起一套视觉或结构。先搭全页骨架，再填内容和图表；所有颜色、字体和关键布局选择都必须从短设计计划派生。
8. **按检查角度审查**：从事实保真、主题契合、美学一致性、字体层级、布局网格、内容塑形、动效克制、可访问性、响应式和分享性逐项检查；未通过就修正。

## plan.md 必须包含

- 受众 / 用途：谁读，读完要做什么。
- 短设计计划：基于 brief 与内容信号 brainstorm 2-3 个方向；每个方向包含 Color、Type、Layout、Signature。
- 相对独特性审查：哪些部分像默认答案，改了什么，为什么改；确认后选择 1 个方向。
- 首屏策略：用什么主题领域代表物开篇，领读什么，如何形成焦点和图地关系。
- 信息结构与版式策略：拓扑、骨架、导航、章节版面、转场节奏、宽度档、移动端降级。
- 逐章内容设计表：每章的内容形状、章节版面、呈现形式、排版处理、证据贴附方式。
- 设计契约：tokens、字体角色、网格 / 宽度档、导航类型、章版面映射、动效策略、关键对比度、泛模板自检。
- checklist：写 HTML 前确认设计契约完整；交付前按检查角度逐项签收。

## HTML 要求

- 使用 CSS tokens 管理颜色、字体、间距、边线、宽度档和动效参数。
- 桌面端要真实使用横向空间；移动端无页面级横向滚动，长表和代码块可局部滚动。
- 导航若存在必须可用：锚点能跳、当前章可感知、键盘可达、小屏可降级。
- 图表与图示继承页面 token，不另起一套颜色和字号；颜色不能是唯一编码。
- 标题、导语、标签、注释和图表文案要经过编辑，不输出模板腔。

# Reference: Aesthetic Direction

# 01 · 短设计计划

本文件用于 `plan.md` 的「短设计计划」阶段。目标不是挑一个好看的皮肤，而是先 brainstorm 2-3 个能从报告所属领域、读者任务和内容气质里推导出来的设计方向，再收敛为一套紧凑的视觉基因：Color、Type、Layout 和 Signature。

先完成本文件，再进入 `02-layout-and-content-design.md`。不要一边写 HTML 一边找风格。

## 1. 提取内容信号

只记录能帮助确定视觉世界的信号：

- **领域**：金融、教育、城市、医疗、AI、制造、政策、消费、游戏、能源等。
- **场景与工具**：账本、控制台、地铁图、课表、病历、试验台、工单、地图、航线、仪表盘。
- **物理质感**：纸张、玻璃、金属、网格、扫描线、墨迹、地形、档案、终端、标牌。
- **内容任务**：解释、比较、决策、复盘、预警、说服、检索、展示。
- **情绪温度**：冷静、紧迫、精密、开放、沉稳、实验性、公共性、纪实感。

这些信号不等于页面元素清单。它们用于推导风格，不用于机械堆装饰。

## 2. 选择首屏代表物

首屏从主题领域中最具代表性的事物或机制开篇。它可以是标题、图片、动画、实时演示、互动结构或视觉隐喻。

选择标准：

- 它属于这个领域，一眼能建立“这是什么世界”。
- 它能承载报告主题，而不是只负责好看。
- 它不是通用模板：大数字 + 小标签 + 统计卡 + 渐变强调只在数字本身就是最自然入口时使用。
- 它不会制造事实断言。视觉隐喻可以来自领域，页面里的数字、案例、来源和结论强度必须来自原报告。

## 3. Brainstorm 2-3 个短设计方向

在 `plan.md` 中先列候选，再选择。候选必须明显不同，至少一个明暗相反；每个候选都必须说明它与内容信号的联系，不能只是风格名或视觉情绪。

每个候选用 compact token system 表达：

```text
方向名：
  内容联系：来自哪些领域、工具、材料、证据关系或读者任务
  Color：4-6 个命名 hex 值，每个说明语义用途
  Type：display / body / utility 字体角色
  Layout：一句话概念 + ASCII wireframe
  Signature：这页唯一会被记住的设计元素
```

选择时写明：

- 为什么选中方向最贴合内容任务。
- 为什么落选方向不如它。
- 把这套方向换到完全不同主题的报告上是否还成立；若成立，说明方向太通用，必须改到能体现当前内容。

## 4. 配色

配色先由主题决定色相，再由规则保证协调与可读性。

- **base hue**：从领域和情绪温度来，不从个人偏好来。
- **中性色**：不要纯灰；背景、正文、边线用同一 base hue 的低 chroma 版本，形成同一个色温。
- **强调色**：一个主强调色，最多一到两个辅助色。每个非中性色必须有语义用途，如风险、机会、引用、当前状态。
- **禁忌**：无语义的彩虹色、紫蓝渐变默认 hero、为“科技感”随手加高饱和蓝紫。

## 5. 字体

字体是页面性格的一部分，不只是内容载体。

- **display**：负责标题、首屏焦点和强记忆点，要有明确气质。
- **body**：负责长文阅读，要稳、清楚、耐读。
- **mono / numeric**：负责数字、代码、时间戳、表格和坐标感。
- display 与 body 要形成角色差异：一个有性格，一个克制耐读。不要两个都抢戏，也不要两个都平。
- 不要使用其他项目常用的字体系列作为默认答案。Inter / Roboto / Arial / system stack 不应成为主角。
- 中文正文必须有合适的中文字体兜底，如 Noto Sans SC / Noto Serif SC / 思源黑体 / 思源宋体。
- 数字密集处使用 `font-variant-numeric: tabular-nums`。

## 6. 纹理、材质与氛围

纹理和氛围是建立领域感的高杠杆手段，但必须退到内容之后。

原则：

- 纹理必须来自主题领域，通过换报告测试。
- 低对比、低频率、低存在感，保证图地关系。
- 优先用 CSS / SVG 手写，保持单文件轻量。

## 7. 动效与氛围

动效服务主题、阅读或信息理解，不是散落的特效。

护栏：

- 不反复骚扰读者；入场动画通常只发生一次。
- 不让动效压过文字和证据。
- 必须提供 `prefers-reduced-motion` 降级。

## 8. 不可遗忘点

每个报告页面都需要一个能被截图记住的结构。它可能是：

- 主题领域代表物的首屏构图。
- 一个独特的图表或流程装置。
- 一种贯穿全页的版面机制。
- 一个能表达报告核心关系的视觉隐喻。

检查问题：

- 任意关键屏被截图发出去，别人能凭哪个点记住这是这份报告？
- 这个点来自主题领域和内容任务，还是通用装饰？
- 它在首屏或核心章节真实落地了吗？

# Reference: Layout and Content Design

# 02 · 版式与内容设计

本文件用于 `plan.md` 的「信息结构与版式策略」和「逐章内容设计表」。它在美学方向之后使用：美学方向决定页面的世界，版式与内容设计决定读者如何穿过这个世界。

核心原则：**结构即信息**。布局、编号、标签、分隔符、导航、章节版面、图表和动效都必须传递真实的信息关系。

## 1. 先定阅读层级

为整页和每章分别回答：

- 第一眼看什么：主题代表物、核心判断、主图、关键冲突、任务入口。
- 第二眼看什么：支撑证据、分组、对比、流程、风险。
- 第三眼看什么：口径、来源、限制、附录、细节。

再把层级翻译成设计手段：

- 尺度：大标题、主装置、宽块、正文、注释。
- 重量：字重、密度、线条、底色、留白。
- 位置：左上入口、中心焦点、边注、脚注、附录。
- 节奏：密集段之后给呼吸，重要转折处加停顿。

## 2. 选择页面拓扑

不要默认单页滚动。先判断读者是在“读”还是在“用”。

| 拓扑 | 适合 | 代价 |
|---|---|---|
| 单文档滚动 | 研究、复盘、白皮书、叙事，读者通读一遍 | 非线性查阅较弱 |
| 多视图切换 | 多对象、多赛道、多榜单、对等视角 | 需要 DOM 全量、无 JS 降级、移动端降级 |
| dashboard hub | KPI、指标族、监控、经营简报 | 容易变成数字墙，必须有下钻结构 |
| 向导 / stepper | 决策件、流程、方案评估 | 不适合跳读和并行比较 |

如果选择非滚动拓扑，必须保证所有内容仍在 DOM 中，JS 关闭时顺序可读，移动端不会横向溢出。

## 3. 选择页面骨架

骨架决定横向空间怎么用。

| 骨架 | 适合 | 要点 |
|---|---|---|
| 单栏长读 | 连续论证、叙事、备忘 | 正文走稳定 measure，图表可出栏 |
| 主栏 + 边栏 | 来源、术语、口径、TOC、限制很多 | 边栏服务参照，不当装饰 |
| 宽幅多区网格 | 多对象比较、数据密集、市场地图 | 区内正文仍保持可读行宽 |
| 受限正文 + 全幅特写 | 专题、叙事、核心装置 | 全幅必须被内容挣得 |

所有骨架共享同一套网格和宽度档。正文、图表、卡片、流程节点、边注和导航都要归位，避免各自居中、长长短短。

## 4. 导航与结构元素

导航和编号都不是装饰。

导航选择：

- 短且线性的报告：通常无导航，最多进度提示。
- 长且需要跳读：TOC、scrollspy、锚点、回顶。
- 多视图 / dashboard：tab、segmented、磁贴入口或分页。
- IA 5-7 个并列项：顶栏可行。
- IA 超过 7-9 个或需要持续参照：侧栏更稳。

结构元素使用规则：

- 编号只用于真实序列、阶段、步骤、时间线、排名或条款。
- 标签只用于真实分类、状态、证据类型、风险等级或口径。
- 分隔符用于分组、节奏或状态变化，不用于填空。
- 眉标应传递当前位置、类别或证据属性，不写模板腔。

## 5. 章节版面

每章都要选择版面。构图不是首屏特权。

| 章节版面 | 适合 | 降级 |
|---|---|---|
| 单列流 | 连续论证、必须按序读 | 仍要导语、拉引、提块、小标题 |
| 双栏对照 | 新旧、多空、A/B、政策前后 | 小屏上下交替 |
| 主文 + 边注 | 来源、口径、限制、hedge 密集 | 小屏内联注释 |
| sticky 分屏 | 一张核心图讲完整章 | 小屏图在上、文在下 |
| 不对称网格 | 一个主判断 + 多个支撑件 | 小屏按主次顺序堆叠 |
| 全幅破格 | 核心装置、关键图表、章节转折 | 小屏收回安全边距 |
| 横向画廊 / small multiples | 多个同构对象并比 | 小屏改为可滚动或两列 |

**这张表是词汇表，不是菜单。** 全部从表里选会得到家族相似的页面。要求：

- **至少一个章节版面是为这份内容自创的、表里没有的**，从结构想法推导，在 plan 写明它为什么只属于这份内容。
- 自创版面同样要给小屏降级。

在 `plan.md` 写成：

```text
章节 -> 内容形状 -> 章节版面 -> 呈现形式 -> 排版处理 -> 证据贴附
```

## 6. 内容塑形

Markdown 是素材，不是版面。逐段或逐判断识别信息形状，再决定呈现。

| 信息形状 | 合适呈现 |
|---|---|
| 时间 / 演进 / 步骤 | 时间线、阶段轴、步骤条 |
| 对比 / 取舍 / 多方 | 双栏对照、矩阵、并列表 |
| 层级 / 递进 / 衰减 | 阶梯、树、缩进层级 |
| 因果 / 流程 / 链路 | 流程链、因果链、泳道图 |
| 构成 / 占比 | 100% 条、比例条、分解图 |
| 多点数值 / 可比量级 | 柱、条、折线、斜率、散点、small multiples |
| 定义 / 口径 / 术语 | 定义表、口径表、悬挂缩进 |
| 并列要点 | 索引行、规则线列表 |
| 判断 + 依据 | 判断提块 + 紧邻证据与来源 |
| 长论述 | 导语、拉引、小标题、边注、关键判断提块 |

避免三种墙：

- 文字墙：连续多段纯正文，只加粗不算设计。
- 表格墙：连续多张表，或把所有可比数字都拍成表格。
- 卡片墙：有主次、顺序、因果的内容被做成等权卡片。

## 7. 图表与图示

图表不只是“把数字画出来”，它要同时做到断言守恒、可读、统一、好看。

硬规则：

- 原文给数字，才画带刻度的量化图。
- 原文只有定性关系，只做排序、相对长度或无刻度表达。
- 柱 / 条图基线从 0。
- 用位置和长度优先，不滥用饼图、环图、3D、面积团。
- 颜色不是唯一编码，必须配合位置、形状、标签或线型。
- 图表字号、线宽、间距、颜色继承页面 token。

节点型图示：

- 同层节点等宽等高，走网格。
- 连接线有统一样式，不用默认箭头字符堆。
- 主方向一致，少交叉。
- 配色克制，不每框一个 hue。
- 标签分层：类型弱、主信息强、条件就近。

## 8. 证据贴附

证据应该贴近它支持的判断。

- 关键数字旁标单位、口径、来源。
- 限制、hedge、数据缺口靠近相关判断。
- 反方证据不要藏在文末。
- 附录承接细节，但不能让核心证据离判断太远。

## 输出格式

在 `plan.md` 中输出：

```text
[信息结构与版式策略]
阅读层级：
页面拓扑：
页面骨架：
导航：
转场与节奏：
结构元素使用规则：

[逐章内容设计表]
1. 章节名：
   内容形状：
   章节版面：
   呈现形式：
   排版处理：
   证据贴附：
   小屏降级：
```

# 03 · 设计契约

本文件用于写 HTML 前。设计契约是 `plan.md` 末尾的开工门禁：它把短设计计划、版式策略和内容设计压成 HTML 必须实现的清单，防止写着写着退回默认模板。

契约不是事后总结。没有契约，不写 HTML。

## 1. 契约必须回答的问题

- 页面基于哪个短设计计划和 compact token system？
- 首屏用什么主题领域代表物开篇？
- 哪些 token 必须出现在 `:root`？
- 字体角色是什么，是否真实加载？
- 页面使用哪些宽度档和网格？
- 每章对应什么版面？
- 哪些图表 / 图示必须实现？
- 哪些动效和氛围层必须实现，如何降级？
- 哪些事实边界不能越过？
- 哪些设计选择只属于这份报告？如果换到另一份报告仍成立，写明要改掉的地方。
- 写完后按哪些角度审查？

## 2. plan.md 推荐结构

## 3. tokens 契约

至少声明这些 token 类型，数值来自选定 compact token system 和版式策略：

```css
:root {
  /* color */
  --bg: ...;
  --surface: ...;
  --surface-2: ...;
  --text: ...;
  --muted: ...;
  --line: ...;
  --accent: ...;

  /* type */
  --font-display: ...;
  --font-body: ...;
  --font-mono: ...;
  --step-0: ...;
  --step-1: ...;
  --step-2: ...;
  --step-3: ...;

  /* space */
  --s1: ...;
  --s2: ...;
  --s3: ...;
  --s4: ...;
  --s6: ...;
  --s8: ...;
  --s12: ...;

  /* layout */
  --measure: ...;
  --wide: ...;
  --page-pad: ...;

  /* shape and motion */
  --radius: ...;
  --line-w: ...;
  --ease: ...;
  --dur: ...;
}
```

要求：

- 间距走有限标度。
- 字号走比例系统。
- 连续正文只有一个 measure。
- 宽块、边栏、全幅都有明确用途。
- 关键文字 / 背景、图形 / 背景对比度写出。

## 4. 泛模板自检门禁

写 HTML 前，必须在 `plan.md` 中完成一次反向检查：

```text
泛模板自检：
这套视觉若换到另一份不同领域报告，哪些地方还成立？
哪些地方因此显得过于通用？
将修改哪 1-3 个设计选择，让首屏、字体、结构或图示更贴合当前报告？
```

要求：

- 自检发生在写 HTML 前，不是交付后的补充说明。
- 至少检查首屏代表物、字体角色、配色语义和章节版面机制。
- 若所有设计选择都能无损迁移到另一份报告，必须回到短设计计划阶段重选至少一个关键选择。

## 5. 章版面映射

写 HTML 前，逐章声明版面：

```text
章版面映射：
0 首屏 = 全幅代表物 + 主标题构图
1 总览 = 不对称网格
2 对比 = 横向画廊 / small multiples
3 证据 = 主文 + 边注
4 流程 = sticky 分屏
5 附录 = 单列流 + 贯通表格
```

HTML 写完后逐章对账。若 DOM 里没有对应布局，说明实现偏离契约。

## 6. HTML 前 checklist

写 HTML 前逐项确认：

- [ ] 短设计计划已选定，且不是通用模板。
- [ ] 首屏代表物来自主题领域，而不是默认大数字 / 三卡片。
- [ ] 配色、字体、纹理、动效和不可遗忘点已写入 plan。
- [ ] 信息结构、页面拓扑、骨架、导航、转场已写入 plan。
- [ ] 每章都有内容形状、章节版面、呈现形式和证据贴附方式。
- [ ] tokens、字体角色、宽度档、章版面映射已声明。
- [ ] 图表 / 图示清单已确定，且没有发明数据。
- [ ] 响应式降级已确定。
- [ ] 事实边界已写明。
- [ ] 泛模板自检已完成，过于通用的选择已修改。
- [ ] 检查角度已列出。

## 7. HTML 实现纪律

- 只实现 plan，不在 HTML 阶段重新发明风格。
- 先搭全页骨架和章节容器，再填内容。
- 每填完 2-3 章，对照章版面映射，防止后半段退回单列。
- 图表和图示使用页面 token，不另起一套视觉系统。
- 所有交互和动效都必须有无障碍与 reduced-motion 降级。
- 如果发现契约有问题，先回 `plan.md` 修改契约，再改 HTML。

# 04 · 检查角度

本文件用于 HTML 完成后的审查。按角度检查，而不是只问“有没有做完”。任何失败项都要修正后再交付。

## 1. 事实保真

- 没有发明数字、日期、来源、作者、公司、案例、排名、地图点位、图表数据或结论强度。
- 视觉隐喻没有变成事实暗示。
- 每个关键判断都能回到原报告。
- 条件、限制、hedge 没有被删成绝对断言。
- 缺失信息被标为“原文未给出”“数据缺口”“需补充”，没有被补写。

## 2. 主题契合

- 首屏以主题领域中有代表性的事物或机制开篇。
- 这套风格换到完全不同主题上会不成立。
- 配色、字体、纹理、动效和不可遗忘点都能追到领域或内容任务。
- 页面没有落入通用紫蓝渐变、三卡片 hero、纸色档案默认皮肤等套路。

## 3. 美学一致性

- 全页共享同一套颜色、字体、网格、线条、圆角和动效语言。
- 有变奏，但变奏服务章节差异，不是每章一个系统。
- 纹理和氛围层保持在背景，不压正文和证据。
- 强调色有语义用途，没有大面积滥用。

## 4. 字体与层级

- display / body / mono 角色清楚，字体真实加载。
- 标题字体和正文字体有气质差异。
- 中文正文有合适字体覆盖。
- 字号走比例系统，不是随手数字。
- 第一眼、第二眼、第三眼的阅读路径清楚。

## 5. 结构与网格

- 正文、图表、注释、卡片、流程节点和导航都落在同一套网格。
- 连续正文只有一个 measure。
- 右边缘只落在少数几个明确宽度档，不长长短短。
- 桌面端真实使用横向空间，不是一根窄列悬在中间。
- 移动端无页面级横向滚动。

## 6. 版式与内容塑形

- 每章版面与 plan 的章版面映射一致。
- 除对等模板章外，章节之间有内容驱动的版面差异。
- 长论述不是原样照贴，至少有导语、拉引、小标题、边注或判断提块。
- 没有文字墙、表格墙、卡片墙。
- 编号、标签、眉标和分隔符都承载真实信息。

## 7. 图表与图示

- 原文给数字才画带刻度的图。
- 定性关系没有被画成精确量化。
- 图表使用位置 / 长度优先，避免饼图、环图、3D 和装饰性 chartjunk。
- 节点图同层等宽等高、连接线统一、方向清楚。
- 图表和图示继承页面 token。
- 颜色不是唯一编码，关键值直接标注。

## 8. 动效与交互

- 动效服务主题、层级、流程、图表揭示或章节转场。
- 没有到处 fade-in、hover 花活或自定义光标等零散特效。
- 动效不影响二次阅读。
- `prefers-reduced-motion` 有降级。
- 导航、tab、按钮、链接的焦点态和当前态清楚。

## 9. 可访问性与分享

- 语义标签完整：`header`、`nav`、`main`、`section`、`aside`、`footer` 按需使用。
- 标题层级合理。
- 文本对比度达标。
- 链接文本有意义。
- 表格有清楚语义，必要时有 caption。
- 有 `title`、`description`、`viewport`。
- 单文件 HTML 可直接打开和分享。
- JS 关闭时关键内容仍可读。

## 10. 视觉验证

- 环境支持时，用浏览器截图检查桌面端和移动端。
- 至少检查首屏、一个核心章节、一个图表 / 图示区域和最长表格或最长文本块。
- 截图中不得出现文本重叠、内容被裁切、移动端页面级横向滚动、首屏焦点偏离、图表标签不可读。
- 若无法截图，最终回复中说明未验证视觉截图，并改用静态检查覆盖布局、响应式和可访问性风险。
